# FoxBridge 0.6

Рабочий учебный прототип на Qt для Windows 11. Использует прокси встроенного Firefox VPN через авторизацию вашего Mozilla Account из локального профиля Firefox. Это неофициальный клиент; Firefox и Mozilla не участвуют в его разработке.

## Запуск готового приложения

1. Распакуйте весь архив `FoxBridge-Windows.zip`.
2. Запустите `FoxBridge.exe` внутри папки `FoxBridge`. Папка `_internal` должна оставаться рядом с exe. Python устанавливать не нужно.
3. Программа прочитает профиль Firefox по умолчанию. При необходимости выберите другой профиль и нажмите «Обновить из Firefox». Если Firefox не найден, откройте «Настройки» и укажите файл `profiles.ini` через «Обзор…» или вставьте путь вручную. Нужен именно файл, не папка профиля.
4. Выберите сервер и нажмите «Включить прокси». Статистика Net.Coffee загрузится автоматически: на главном экране появится score. Кнопка «Подробности» открывает IP, ASN, локацию, тип сети, признаки риска и полный ответ API. Обновление доступно и на главном экране, и в подробностях.
5. Дождитесь актуального score и определения пояса: рядом с запуском отобразится `TZ` нового терминала. Затем нажмите «Открыть PowerShell с прокси» и запустите `claude` или `codex` в открывшемся окне. Если score/пояс отсутствует, проверка завершилась ошибкой или канал недоступен, запуск и копирование команд заблокированы.

Можно скопировать команды и выполнить их в существующем PowerShell перед запуском CLI. Приложение задаёт `HTTP_PROXY`, `HTTPS_PROXY`, `WS_PROXY`, `WSS_PROXY`, а локальные адреса исключает через `NO_PROXY`. Переменные действуют только в запущенном терминале и его дочерних процессах. Программы могут иметь собственные настройки, которые переопределяют эти переменные, либо не поддерживать прокси.

Для Codex с поддержкой `--no-daemon` в этом терминале создаётся временная функция `codex`: интерактивный запуск, `resume`, `fork`, `exec` и `review` получают этот флаг автоматически. Это предотвращает подключение к общему серверу, который мог быть запущен раньше с другими сетевыми настройками. Функция действует только в текущем PowerShell; файлы настроек и профили PowerShell не меняются. Команды управления сервером, `agents`, явно заданные удалённые подключения и `apply` передаются исходной программе без добавления флага. Возможности уже работающего общего сервера не изменяются. Если установленный Codex не поддерживает флаг, выводится предупреждение, обёртка не создаётся. Запуск по полному пути к exe обходит функцию PowerShell.

Закрытие приложения или кнопка выключения останавливают локальный сервер и разрывают его активные соединения. PowerShell остаётся открытым; команды в нём по-прежнему настроены на этот прокси и без работающего FoxBridge могут получать ошибку соединения.

## Часовой пояс запуска

FoxBridge 0.6 выбирает пояс из поля `timezone` в ответе Net.Coffee `iprisk`. При отсутствии поля используется таблица «страна → представительный пояс» из просмотренного скрипта страницы Net.Coffee. Это приблизительный вариант, особенно для США, Канады, Австралии и других стран с несколькими поясами; он обозначен в интерфейсе и подробностях. Неизвестный или некорректный пояс блокирует запуск. При некорректном заполненном поле API автоматической подмены оценкой по стране нет.

Пояс проверяется по базе Qt, текущее смещение рассчитывается с учётом правил перехода времени. Значение передаётся как переменная `TZ` окружения нового PowerShell, повторно задаётся в его стартовых командах и наследуется обычными дочерними процессами. Windows, системное время и настройки Firefox не меняются. В подробностях на вкладке «География» видны системный пояс, выбранный TZ, источник и приблизительность определения.

**Это настройка TZ окружения, а не универсальный спуфер часового пояса.** Она меняет результат API времени только у программ и сред, поддерживающих TZ. Node.js на этой Windows проверен: и родительский, и дочерний процесс возвращают выбранный IANA-пояс через Intl. Нативный Codex и конкретный установленный Claude Code в полном рабочем сеансе на этот эффект не проверены. PowerShell/.NET/Windows API и ранее запущенный браузер могут продолжать видеть системный пояс. Изменение содержимого HTTPS и внедрение кода в процессы не выполняются. Проверка Bun-режима установленного claude.exe не предоставила доступ к диагностическому JS; это не считается подтверждением совместимости Claude.

Готовность кнопки означает, что текущий score получен и корректное значение TZ подготовлено к передаче, а не что все программы подтвердили подмену. Нулевой score тоже является полученной оценкой; минимальный порог качества не задавался. Перезапуск FoxBridge, смена сервера/профиля и неудачное обновление статистики требуют новой успешной проверки перед открытием терминала. Приблизительное значение не превращается в точное от совпадения смещения.

Уже открытые терминалы и CLI не обновляют окружение автоматически. После смены сервера или изменения выбранного пояса закройте старые CLI/терминалы и откройте новый из FoxBridge. Браузерная авторизация требует отдельной настройки пояса браузера, если она нужна: TZ терминала не настраивает Firefox. Совпадение пояса и высокий score Net.Coffee не гарантируют отсутствие проверок аккаунта, не являются официальной оценкой Anthropic и не изменяют известную сервису авторизацию аккаунта.

## Восстановление соединения и границы защиты

При ошибке соединения с сервером Firefox или авторизации локальный порт остаётся открытым, но новые запросы получают HTTP 503 с Retry-After. Запросы не направляются напрямую к сайтам. В интерфейсе отображаются причина, время до следующей проверки и кнопка «Повторить подключение сейчас». Ошибки входа, исчерпанной квоты, ограничений частоты и сертификата выделяются отдельно. После обновления VPN-авторизации в Firefox можно нажать повтор подключения: приложение перечитает токен с диска без закрытия терминала.

Восстановление проверяет одна фоновая задача. Интервал увеличивается примерно с 2 до 60 секунд, для входа/квоты/сертификата установлены минимальные интервалы. Retry-After сервера (число секунд или HTTP-дата, до часа) учитывается; кнопка не обходит ограничение частоты и квоты. При успешном TCP/TLS/авторизованном CONNECT канал снова принимает запросы на прежнем локальном порту. Автоматической смены страны/сервера нет. Действующие потоки остаются на исходном сервере до завершения или разрыва; HTTP-запросы и генерации не воспроизводятся переходником автоматически. Повтор запроса самим CLI возможен и зависит от CLI.

Состояние проверяется также фоновым CONNECT раз в 30 секунд. Это проверка доступности прокси, а не гарантия доступности каждого сайта. Ошибка отдельного назначения не обязана означать падение всего канала. Срок пропуска рассчитывается по фактическому `exp` относительно текущего времени; истёкшие и ещё не действующие пропуска отклоняются. Явный отказ авторизации или квоты сбрасывает сохранённый пропуск. Проверка TLS остаётся включённой при каждом повторе.

**Это защита соединений, уже направленных в FoxBridge, а не системный киллсвич.** Программы, переопределяющие или игнорирующие переменные прокси, не блокируются. Нет перехвата произвольных TCP/UDP, DNS всех процессов, фильтров Windows или защиты от другого локального приложения, занявшего порт после остановки FoxBridge. Наличие score не доказывает отсутствие утечек. Нельзя считать все подключения CLI проверенными лишь потому, что одна генерация работает.

Цель для Claude Code/Codex — направлять через прокси не только модельные запросы, но и их авторизацию, обновление токенов, телеметрию и коннекторы поставщика. Начинайте штатный вход из PowerShell FoxBridge, а браузерную ссылку открывайте в Firefox с включённым встроенным VPN. Локальный callback остаётся локальным благодаря NO_PROXY. Браузерный вход и весь сетевой путь установленных CLI/субагентов ещё требуют отдельной сквозной проверки. Прокси не скрывает личность авторизованного аккаунта.

Обычные дочерние процессы наследуют настройки прокси. Отдельные MCP-серверы и скрипты могут очистить окружение или использовать собственные настройки. Для стороннего Context7/Google Drive допустимость прямого соединения зависит от того, требуется ли скрывать IP от этого сервиса; коннекторы через OpenAI/Anthropic входят в цель проксирования. Их настройки автоматически не переписываются. Никакой дополнительной фоновой отправки данных или генерации моделей для проверки приложения нет.

## Что реализовано

- Интерфейс Qt / PySide6, выбор профиля Firefox, маскированный аккаунт.
- Настройки источника профилей: ручной путь к `profiles.ini`, выбор файла, проверка существующих профилей и возврат к автоматическому поиску. По умолчанию используется `%APPDATA%\Mozilla\Firefox\profiles.ini`. Относительные пути профилей разрешаются относительно выбранного INI-файла. Настройка сохраняется в `foxbridge-settings.json` рядом с приложением; в этом файле нет авторизации или токенов. Для изменения источника сначала выключите прокси.
- Список доступных HTTPS CONNECT-серверов из сохранённого списка Firefox. Серверы, требующие платного доступа, скрываются для бесплатного аккаунта; карантинные серверы исключаются.
- Получение краткоживущего пропуска у Guardian и обновление до истечения срока действия. При отказе авторизации прокси — одна попытка обновить пропуск.
- HTTP-прокси только на `127.0.0.1`, порт по умолчанию 8765, поддержка CONNECT и обычных HTTP-запросов. Потоковая передача в обе стороны без буферизации полного ответа.
- Реальные лимит, остаток и дата сброса квоты из ответов Mozilla. Единицы отображения — ГиБ (1024³ байт), не десятичные ГБ. Обновление раз в минуту.
- Проверка IP и статистики Net.Coffee: сначала `https://claude.ai/cdn-cgi/trace`, затем публичные GET-запросы `https://ip.net.coffee/api/geoip/{IP}` и `https://ip.net.coffee/api/iprisk/{IP}`. Все запросы идут через локальный прокси. Учётные данные Mozilla/Codex сервису Net.Coffee не передаются. Обращений к `/api/session` и отправки прямого IP компьютера нет.
- На главном экране из IP-статистики показан только score 0–100, источник и время получения. IP, ASN, провайдер, CIDR, тип сети, признаки VPN/proxy/Tor, сведения о рисках и источники географии доступны в отдельном окне с четырьмя вкладками, включая полный JSON.
- Итоговый score учитывает региональную корректировку страницы Net.Coffee. Это правило стороннего сайта, а не официальная политика Anthropic. Исходный `trust_score` и факт корректировки видны в подробностях. Неизвестный score показывается прочерком, а не нулём.
- Net.Coffee может кэшировать оценку по подсети. Если IP в ответе отличается, score принимается только когда и фактический IP, и IP-представитель принадлежат указанному CIDR. Область оценки обозначена в подробностях. Разные источники географии могут расходиться; данные отображаются раздельно. Время запроса не означает, что база самого сервиса обновилась в этот момент.
- Обновление запускается при подключении и вручную. Повторные нажатия не создают параллельные проверки; минимальный интервал — 10 секунд. При HTTP 429 учитывается Retry-After. Проверка выполняется в фоне и не блокирует работу CLI или отключение прокси.
- При неудаче сохраняется предыдущий score с явной отметкой об устаревании. Частично полученные данные доступны в JSON последней попытки. При смене подключения старые результаты очищаются, запоздалые ответы старой сессии игнорируются. При сбое геолокации доступный score всё равно отображается. Автоматической подмены Net.Coffee другим сервисом нет.
- В подробностях показана задержка нового TCP/TLS/CONNECT-соединения к claude.ai, время сессии, число соединений и переданные байты. Задержка не является ICMP-пингом или скоростью скачивания, а счётчики сессии не заменяют серверный счётчик квоты.
- Кнопка запуска PowerShell с прокси, копирование команд, сообщения об ошибках без токенов.

## Авторизация и пределы прототипа

Самостоятельного OAuth-входа пока нет. Программа читает только существующую авторизацию и настройки Firefox, не изменяя профиль. При отсутствии или истечении OAuth-токена включите встроенный VPN в Firefox, дождитесь подключения и нажмите «Обновить из Firefox» в FoxBridge. Если Firefox не сохранил актуальные данные на диск, может потребоваться обычное закрытие и повторный запуск браузера. Доступ к VPN должен быть уже предоставлен вашему аккаунту.

Список серверов читается из `browser.ipProtection.locationListCache` в профиле, поэтому актуальность списка зависит от обновления Firefox. Профиль перечитывается по кнопке. Смена сервера доступна после выключения прокси. Поддерживаются текущие HTTPS CONNECT-серверы `*.fastly-masque.net`; MASQUE/UDP и TUN не реализованы.

FoxBridge не меняет системные прокси, DNS, маршруты Windows, настройки Quattro или брандмауэра. Он не направляет в туннель все приложения компьютера. Учитываются только подключения к его локальному порту. Если используется WSL или контейнер, доступ к Windows localhost зависит от их сетевого режима; этот сценарий ещё не проверен.

Пароли не запрашиваются. OAuth-токен отправляется только `https://vpn.mozilla.org/`; пропуск прокси — только выбранному прокси. Токены не записываются в настройки, журнал или командную строку. Проверка цепочек TLS и имён серверов включена, содержимое HTTPS не расшифровывается переходником. Прямого подключения к сайту при отказе удалённого прокси нет. Начальная проверка использует `example.com:443`, статистика — `claude.ai:443` и `ip.net.coffee:443`; это расходует небольшой объём квоты. Статистика хранится только в памяти приложения. API Net.Coffee используется самой страницей сайта, но его стабильность и условия для сторонних клиентов не документированы.

Доверенные CA находятся в `cacert.pem`, источник: https://curl.se/docs/caextract.html. Контрольная сумма закреплена в коде; произвольная замена файла приводит к отказу запуска соединений. Обновление набора требует проверки нового официального файла и изменения контрольной суммы в исходнике.

## Запуск из исходников

Python 3.12+ для Windows:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```
