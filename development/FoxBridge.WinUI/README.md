# FoxBridge · WinUI 3

## TUN для компьютера

Доступны режим для CLI и TUN для TCP интернет соединений компьютера.
Без прав администратора показывается предупреждение и блокируется подключение TUN.
Настройка сохраняется в `tun` файла настроек. Системный HTTP прокси не меняется.
До старта TUN через локальный прокси обязательна проверка IP и Net.Coffee.
Без корректной оценки и актуального доступного канала TUN не запускается,
локальный прокси останавливается. Успешная проверка передаётся интерфейсу
после события подключения без повторного запроса статистики.
DNS идёт через HTTPS внутри локального прокси; прочий UDP внутри TUN отклоняется.
Локальные и специальные маршруты могут обходить TUN. Постоянного kill switch нет.

`Install-TunEngine.ps1` загружает sing-box 1.14.4 и проверяет архив SHA256.
Перед запуском проверяется SHA256 EXE. Движок запускается отдельным процессом
в собственной скрытой консоли. Закрытие stdin останавливает его через Ctrl+Break.
Job object завершает дочерний движок при аварии управляющего процесса.
Python ядро привязывает свои внешние TCP сокеты к исходным интерфейсам.
IP адреса управляющего API Mozilla и выбранного сервера разрешаются до TUN,
чтобы обновление токена и восстановление канала не зависели от DNS через канал.
При смене сети требуется переподключение.

Проверены конфигурация закреплённой версии движка, его остановка по EOF без
сетевых интерфейсов, проверки прав, сборка и предупреждение в настоящем окне.
Перехват трафика через TUN с правами администратора пока не проверен.

## Проверка компонентов и сохранение выбора

При старте проверяются файлы Backend и доступный Python версии 3.12 или новее.
Поддерживаются python.exe, python3.exe и py.exe из PATH. Ядро запускается найденным
интерпретатором. В настройках выводятся результат, подсказка по установке Python
и кнопка повторной проверки. Для отсутствующих .NET и Windows App Runtime
используются встроенные сообщения native apphost и bootstrapper до загрузки UI.

Порт и выбранный профиль сохраняются в foxbridge-ui-settings.json.
Сервер запоминается отдельно для каждого профиля по host и port. Порядок серверов
в полученном списке не влияет на восстановление. Если сервер пропал, выбор очищается
и требуется ручной выбор. Загрузка профиля и подключение остаются ручными.
Сохранение через временный файл сохраняет остальные поля при смене profiles.ini.

Проверки: `dotnet run --project ../FoxBridge.WinUI.Checks`.

Первый рабочий интерфейс на C# / XAML / WinUI 3. Отдельный проект рядом с
`FoxBridge-source`; существующая версия 0.6 не изменена.

## Реализовано

- Навигация: подключение, статистика, журнал, настройки.
- Светлая, тёмная и системная тема; перестроение карточек при узком окне.
- Поиск профилей Firefox без сетевых запросов при запуске окна.
- Кнопка загрузки профиля: чтение доступных серверов и квоты через существующее ядро.
- Подключение/отключение, ручной выбор сервера, восстановление того же endpoint.
- Net.Coffee: score, текущий IP, читаемая статистика «параметр — значение» в два столбца
  и блокировка терминала до актуальной оценки/TZ.
- PowerShell с proxy/TZ и существующей обёрткой Codex `--no-daemon`.

Сетевые действия подключены к ядру 0.6 через приватные stdin/stdout дочернего
Python-процесса. Управляющий TCP-порт не создаётся. При закрытии окна ядро
завершается; после таймаута завершается только принадлежащий окну процесс.
PySide6 для нового интерфейса не нужен. Выбор IANA-пояса проверяется средствами
.NET; приблизительная таблица стран остаётся общей со старым приложением.

## Сборка разработчика

Требуются Windows 11, .NET SDK 10, Windows SDK и Python 3.12+ в PATH.
Для запуска нужен .NET Runtime 10 x64 и Windows App Runtime **2.6.4 x64**.
Winapp нужен для настройки/создания проекта, не для запуска приложения.

```powershell
dotnet build .\FoxBridge.WinUI.csproj -c Debug -p:Platform=x64
```

Debug остаётся в `bin/x64/Debug` внутри проекта разработки и не меняет готовую поставку.
Для обновления готового приложения из корня репозитория:

```powershell
& .\development\Publish-Release.ps1
```

Готовый EXE: `../../FoxBridge-WinUI/FoxBridge.WinUI.exe`.
Скрипт публикует Release без PDB, добавляет обязательные XBF и PRI ресурсы,
сохраняет настройки, обновляет единственную готовую папку и ярлык запуска.
Временная поставка находится внутри development и удаляется после обновления.
Архивы и прежние версии удалены. Новые папки поставки с суффиксами не создавать.
Нельзя переносить один EXE без соседних файлов и папки Backend.

Для уменьшения набора зависимостей используются Microsoft.WindowsAppSDK.WinUI
и Microsoft.WindowsAppSDK.Runtime 2.6.4. Общий метапакет с AI, ML, Search, Widgets
не подключается. WebView2 остаётся транзитивной зависимостью WinUI.

Выбрана framework-dependent поставка, без включения .NET/WinAppRuntime.
Для отсутствующего Windows App Runtime включено штатное сообщение bootstrapper.
Отдельный универсальный загрузчик для обеих зависимостей ещё не сделан.
Python пока используется установленный: финальная упаковка ядра в автономный
helper EXE — следующий этап поставки, а не свойство этой сборки разработчика.

Настройки пути profiles.ini сохраняются рядом с EXE в
`foxbridge-ui-settings.json`, без токенов и аккаунтов. Не включать этот файл в архив.

терминал», подпись с фактическим TZ и его источником находится под ней.
Новая подпись не меняет способ проксирования и границы действия TZ.
Статистика: сеть, риски, география, время проверки и частичные ошибки источников.
Форматирование проверяется командой `dotnet run --project ../FoxBridge.WinUI.Checks`.

Статистика теперь размещается в двух колонках пар «параметр — значение»;
при ширине содержимого менее 700 px — в одной. Цвета адаптируются к теме Windows.
По просмотренному 05.11.2026 `https://ip.net.coffee/claude/claude-page.js?v=20260916a`:
VPN/Proxy/Tor/crawler/abuser=true — красный, false — зелёный; жилой IP — зелёный,
нежилой — оранжевый; дата-центр — оранжевый. Score >=50 — зелёный (объединены
оттенки шкалы сайта), 25–49 — оранжевый, <25 — красный. Код ограниченного региона
отмечается красным по списку самого сайта. Это правила Net.Coffee, не политика Anthropic.
Неизвестные и справочные параметры нейтральны; приблизительный TZ и ошибки
источников помечаются как дополнительные предупреждения FoxBridge.

В Debug-сборке есть offline-режим визуальной проверки:
`FoxBridge.WinUI.exe --preview-statistics ABSOLUTE_PATH_TO_JSON`.
Он явно подписывает демонстрационные данные и не читает аккаунты/профили,
не запускает ядро и не подключается к сети. Пример: `../FoxBridge.WinUI.Checks/statistics-preview.json`.

## Firefox и справка

FirefoxSession запускает выбранный VPN-профиль обычным экземпляром Firefox.
WebDriver, RemoteAgent и автоматическая подмена TZ/локали браузера не используются.
Временные сетевые настройки сохраняются и восстанавливаются через
FirefoxProfilePreferences. Существующий user.js сохраняется, cookies и история
не откатываются. Окна закрываются обычным WM_CLOSE только для запущенной цепочки
firefox.exe. Принудительного завершения процессов нет.

Встроенные Readme и FAQ формируются из Help/README.md, копируемого из корневого
README.md при сборке. Разделы разработки остаются в файле и не выводятся в интерфейсе.
